# How this branch is validated

The commands, measurements, negative controls and representation-specific test names below retain their tested revisions. Loose auxiliary files, mark-graph tests, `WriteBuffer*`/`NarOfString*`, temporal string/exec tokens and their checker describe retired mechanisms. Current eager-publication obligations are exercised by `TextStoreTest` in `text-store.cc` and the C boundary tests; legacy-NAR callback ownership is exercised by `transfer_nar_hash_*` and the keyed-batch test. Buffer thresholds, flush timing and token-only compiler checks are retired, not current requirements. Current laws and representation obligations are in `01` §9.10 and `08`; revision-pinned gates and performance are recorded in [09-performance.md](09-performance.md). Historical overlay failures and subsequent real-mount passes remain evidence for those revisions only.

What the checks are for, which suites exist and how each is run, what the differential harness compares against master, which mutations must make which tests fail, what each of the two platforms finds, which measurements stand and by what command, and what is owed. A number here carries its command; a claim without a test that pins it is marked so.

## 1. What is checked

The conditions of `01-specification.md` section 3: **(C1)**, the store after a command equals the reference's up to the renaming the one address induces; **(C1')**, a failing command fails the same way and leaves a store closed under references; **(C2)**, no path of Δ escapes before its object is in the store. The laws of `01` sections 8, 9.9, 9.10 and 9.11: the naming homomorphism (equal names, equal trees), the object hash equal to git's, route independence of the hash, sharing in the object store, the store's relation to its paths, and collection. The checks are of three kinds: the unit and functional suites, which pin each law and each fixed defect by name; the differential harness, which runs master's own functional suite under the reference and under the branch and compares the stores; and the mutation checks, which show that a test discriminates by forcing the change it guards against.

## 2. The suites, one per command line

Meson intersects `--suite` with the tests named on the same line, so a suite and a list of names must never share a command line; every suite below runs on its own.

**Unit tests.** Five binaries, run as `meson test` runs them, with `_NIX_TEST_UNIT_DATA` pointing at the test directory's `data/` (`src/libutil-tests/meson.build`, `src/libstore-tests/meson.build`):

```

build/src/libstore-tests/nix-store-tests
build/src/libfetchers-tests/nix-fetchers-tests
build/src/libexpr-tests/nix-expr-tests
build/src/libflake-tests/nix-flake-tests
```

The branch's tests live in `src/libutil-tests/{merkle-hash,object-hash-sink,object-hash,git,source-accessor-naming,archive,mounted-source-accessor,union-source-accessor,file-content-address}.cc`, `src/libstore-tests/{local-store,object-hash-local-store,object-hash-path-info,object-hash-nar-info,object-hash-worker-protocol,content-address}.cc` and `src/libstore-tests/derivation/round-trip.cc`, `src/libfetchers-tests/{git-utils,fetch-to-store}.cc`, `src/libexpr-tests/{text-store,add-path,nix_api_expr}.cc` and `src/libexpr-tests/value/value.cc`, `src/libflake-tests/lockfile-v8.cc`. What each pins is named in `01` ("The checks the meaning induces" of sections 9.9 and 9.10), `04` (the "Checks" of each component) and `07-defect-ledger.md`'s table.

**Functional tests.**

The third line names the main-suite tests the branch touches or that its defects were found by; the whole main suite is what the Linux package build runs (section 5). `object-hash.sh` and `git-hashing/simple-sha1.sh` have interop blocks, and `interop-old-daemon.sh` and `git-hashing/old-executable-root.sh` are tests of their own, that run only when `NIX_REFERENCE_BIN` names the `bin` directory of a Nix built from master (the two whole tests skip with the suite's helper, exit 77, when it is unset): an old client against the new daemon and a new client against the old daemon, without and with the old side's `git-hashing` feature; a cache the old Nix wrote read by this one; a path this Nix signed verified by the old binary; a SHA-1 git-addressed path the old Nix made read here and refused on copy; the three inputs whose name the old daemon cannot supply; an executable or symlink root the old Nix addressed under the git method, refused on copy. The tests clear the loader environment before running the reference binary; the reference daemon is started with `NIX_REMOTE` empty and stopped by polling and then `SIGKILL`, since it does not always exit on `SIGTERM`.

## 3. The differential harness

`tests/functional/differential/` (its `README.md` describes the files). It runs master's functional scripts, unchanged, under two modes and compares the store afterwards: a **snapshot** is `nix path-info --all --json --json-format 2` with `registrationTime` removed and the store directory blanked, the database tables `ValidPaths` (minus `registrationTime`), `Refs`, `DerivationOutputs` and `BuildTraceV3`, the permanent roots, and the store directory listing (which catches unregistered leftovers), for the main store and for every chroot store under the test root; snapshots are taken at the end of each script and, through a hook in the copied `common/functions.sh`, before every `clearStore`. Each script runs as `tests/functional/meson.build` runs it. A **mode** is a Nix package, the tools PATH, an optional `NIX_CONFIG` fragment, an optional client package and whether to run through a daemon (`modes/*.env.in`: three templates that `prepare-tree.sh` fills into `<dest>/modes/` — `reference.env`; `reference-githash.env`, the reference with `git-hashing` enabled; `branch.env`, the reference tree and bindir with the branch's `nix` first on PATH, its store path from `BRANCH_NIX` or one `sed` — the harness README lists the variables).

Five views, from weakest to strongest: the **name multiset** (`name-multiset.py`: the multiset of object names with the hash part stripped; invariant under the hash churn of nondeterministic inputs; strengthens an exclusion, never turns a DIFF into a SAME); the **renamed view** (`renamed-content.py`, `snapshot.py renamed`: one line per valid object with its name, the digest of its tree after the hash part of every embedded store path is masked and a derivation's path-sorted lists re-sorted, its content-addressedness, and its references' and deriver's names — the same objects with the same bytes up to a name-preserving renaming in the same reference graph by name); its **strict** form, which digests build outputs' bytes too; the **loose** snapshot view (build outputs by path and metadata, unregistered entries with the hash masked), which is the verdict for a reference-against-reference run; and the **strict** snapshot view, which keeps everything. Since the one address every source path differs and the `ValidPaths.hash` column is rendered `git:sha256:<hex>` by the branch and `sha256:<hex>` by the reference, so for a branch-against-reference run the verdict is the renamed view, and the loose view reads DIFF on every test that names a source, as it must. Verdicts per test: SAME-PASS, SAME-SKIP, SAME-FAIL (the same failure on both sides, an environment limit), DIFF; unified diffs are kept beside the B-side snapshots.

```
BRANCH_NIX=<branch nix package> prepare-tree.sh <repo>/tests/functional <tmp>/tree <reference nix>/bin <coreutils>/bin <bash> <version> <system>
export HARNESS_TMPDIR=<tmp>
differential.sh <tmp>/tree/modes/reference.env refA <tmp>/tree/modes/reference.env refB main <scripts...>
differential.sh <tmp>/tree/modes/reference-githash.env reference <tmp>/tree/modes/branch.env branch main <scripts...>
summarize.sh <tmp>/out/summary-<A>-vs-<B>-<suite>.tsv
name-multiset.py <tmp>/out <A> <B> <suite>
renamed-content.py <tmp>/out <A> <B> <suite>
```

The reference side of a branch-against-reference run carries `extra-experimental-features = git-hashing`, which master needs to accept git-named paths (`reference-githash.env`); the branch answers that line with a one-line "has been stabilized" warning. Daemon mode (`HARNESS_DAEMON=1` appended to a mode file) names the branch package as the daemon too (`HARNESS_DAEMON_PACKAGE`), because the client forwards its settings and a daemon that does not know one warns on the client's stderr, which `cli-characterisation.sh` compares. `HARNESS_TMPDIR` must be set — the scripts refuse to run without it — to a resolved, short directory: on macOS `/tmp` is a symlink and the resolved path is what the tests see, since the characterisation tests normalise the working directory, and the daemon socket path must stay under the 104-byte limit.

**What it compares against master, and what it excludes by construction.** Run reference against reference first, the harness is stable on 163 of master's 220 scripts across the seven suites (main 133, ca 25, dyn-drv 11, flakes 34, git 3, git-hashing 3, local-overlay-store 11); 34 skip on macOS (the Linux sandbox, overlayfs, mercurial, manpages, `lang-gc`), one fails identically on both sides (`structured-attrs.sh`, whose `nix develop -c bash -c 'test -n "$out"'` sees `out` only inside a Nix build), and 22 differ between any two runs of master and are excluded from (C1), each with its cause verified at the cited line: the wall clock in a derivation or its output (`check`, `ca/build-trace-delete`, `ca/duplicate-realisation-in-closure`); `$RANDOM` in a derivation or written into `flake.nix` (`extra-sandbox-profile`, `flakes/flakes`, `flakes/inputs`); keys generated per run (`fetchGitVerification`); archives packed at run time (`nix-channel`, `fetchTree-file`, `flakes/build-paths`); a flake evaluated from the test home directory, whose `.cache`, `.local` and profile are copied into the source (`suggestions`, `formatter`, `flakes/run`, `flakes/bundle`, `flakes/config`, `flakes/develop`, `flakes/search-root`); a `path` input's `lastModified` in a lock file (`nix-profile`, `flakes/relative-paths-lockfile`, `flakes/non-flake-inputs`); a `.git` directory inside the copied source (`flakes/shebang`); the environment dump of a content-addressed build (`ca/nix-shell`). Seven more differ between any two *binaries* and are excluded from binary-to-binary comparison: `add-scanning`, `recursive`, `ca/recursive` and the four recursive-Nix tests of dyn-drv bake the directory of the `nix` binary into a derivation. `nix-shell` and `impure-derivations` pass under the loose view with `content-differs`: an environment dump records the build's temporary directory. The name-multiset view is NAMES-EQUAL on every excluded test with a snapshot on both sides.

**Reading a branch-against-reference run.** The verdict is the renamed view; the loose view reads DIFF on every test that names a source, as it must. Three master tests assert the flat hash or a version-7 lock (`add`, `structured-attrs`, `flakes/relative-paths`) and read DIFF by design; the branch tree's versions pass under the branch and fail under the reference. `ca/eval-store` differs under the renamed view because a floating content-addressed derivation's output placeholder is a hash of an input derivation's *renamed* path, which no masking of paths can recover — a limitation of the view, stated. `export-graph` and `nix-shell` are equal under the renamed view and differ only under its strict form (a builder writing paths in path order; an environment dump). Every test the branch rewrote or added was run under the reference and fails there, except `lazy-store-doors` and `ca/floating-git`, which laziness does not touch and which pass under both. The summary TSVs are not kept in the tree; a reader who wants figures re-runs the harness and reads `summarize.sh`'s output.

**The (C2) observer.** `c2-observe.py` reads a command's stdout (or stderr, for `trace` and `throw`) from a second process as the command runs and checks each printed store path as its line arrives — registered in the store's database when `NIX_STATE_DIR` names one, else present on the filesystem — and `C2_ROOT=<dir> c2/run-c2.sh <label> <nix package> <mode>` drives it from a fresh private store over thirteen modes: `drvs` (`nix-instantiate`'s derivation lines), `eval`, `evaljson`, `evalraw`, `match`, `split`, `getctx`, `trace`, `throw`, `repl`, and `lazyeval`, `lazyraw`, `lazyjson`, which build a 4000-file git repository and print its `fetchGit` outPath. Its 300-derivation list (`c2/many-drvs.nix`) makes every serialisation longer than a pipe's stdio buffer, so bytes leave before the command ends. The reading is differential: the branch must never report a path absent where the reference reports it present. Run against the reference, the branch reads present=300 absent=0 in the ten derivation modes on both sides, and in the three mounted-input modes reference absent=1, branch present=1 — `emit` copies the mounted input before printing its path, the intended tightening of `01` section 3. `nix-instantiate --eval` is read-only and prints paths that are not in Δ; the observer reads absent on both sides there, identically. What the observer cannot see: a violation whose output is shorter than the pipe buffer (hence 300), and anything but one process's output — the daemon protocol and files, which coercion-before-build and coercion-before-root protect by construction (`04` section 1.2).

**The measurement scripts** (`tests/functional/differential/measure/`): `workloads.sh` generates the `closure`, `fan` and `files` workloads; `measure-writes.sh` counts the buffer's flushes and batch sizes at talkative verbosity; `count-ops.sh` counts the daemon's worker operations from its debug log; `measure-eval-linux.sh` measures peak resident memory of `nix eval --json` and `nix-instantiate` over N derivations, wrapped as a derivation so a Linux builder runs it. Each takes the binary to measure, so a comparison is two runs, the reference's and the branch's (`MEASURE_ROOT` names their scratch directory). Their results are in section 6.

## 5. The two platforms

**macOS** (Apple Silicon, APFS, clang, per-file compilation; a writable home, Internet, the case hack on): the development platform. It alone can exercise the case hack (`Foo`/`foo` restored as `foo~nix~case~hack~1`, the route-independence check of `01` section 9.11), `.app/Contents` (files the store leaves as written), and APFS's costs, where a hard link is dearer than a small write, so every timing taken here is a direction only.

**aarch64-linux** (gcc, the unity build, sandboxed package builds with no network, ext4 over NVMe): the platform for constants and the gate before a step is done. Run as `nix build --system aarch64-linux .#nix-util-tests.tests.run` (and the other four unit packages) and `nix build --system aarch64-linux .#nix-functional-tests`. What it finds that macOS cannot: gcc's differences from clang (an explicit-object lambda clang accepts can crash gcc; `testing::HasSubstr` written inside `namespace nix` resolves to the test-support namespace `nix::testing` under gcc; a struct holding a reference under `NIX_SUPPORT_ACL` cannot be brace-initialised empty); the unity build's ambiguity between same-named file-local functions and same-named fixtures in two test files; the sandbox's absence of network, so a test that relies on substitution must pass `--option substitute true` on the command line (the CLI otherwise turns substitution off when it detects no Internet), and of the developer's caches, so a test that names a tree reads a fixture-owned `NIX_CACHE_HOME`; rapidcheck seeds that grow past a small generator's domain (a generator must draw from the domain directly, never ask for more distinct values than it holds); shared files at scale (`gc-auto.sh`, the `max-free` decision of `01` section 10); and the build hook's hand-off of every setting to its child, caught only by `cli-characterisation.sh`'s goldens, which compare stderr.

**The ThreadSanitizer gate, on Linux.** At this tree the store run — `LocalStoreObjectsTest.parallelCopyIsTheSequentialCopy`, the materialise and restore tests, the property over generated trees — passes 9 of 9 with no report, the index's writer thread included; the fetchers run — `FetchToStoreLocalTest.*`, `FetchToStoreTest.*`, the memo behind its lock — passes 6 of 6 with no report. The per-file (non-unity) build of the five test packages passes. The parallel copy's soundness (`08` K17) is checked by a thread-sanitised build, not by reading alone. *It cannot be run on macOS here:* the toolchain compiles `-fsanitize=thread` without complaint, but every binary it makes dies before `main` — a ten-line two-thread program included — at `EXC_BAD_ACCESS (code=1, address=0x0)` in `libclang_rt.tsan_osx_dynamic.dylib`'s `__tsan::SlotLock(__tsan::ThreadState*) + 24` (compiler-rt 21.1.8, aarch64-darwin), with no diagnostic of its own. **The range query the design asked for is not possible here, and this is why.** One query per fingerprint at the walk's start — the rows whose encoded key begins with the fingerprint attribute's encoding, `fingerprint` sorting first in `Attrs`'s map order — rests on the walk's nodes sharing one fingerprint and differing in `path`. They do not. `GitSourceAccessor::getFingerprint` returns, for **every** node, `{CanonPath::root, "git-object-v1:<kind>:<that node's own object id>"}`: the fingerprint is the node's content address and the path is always the root. A range over a fingerprint prefix selects exactly the one row the point query already selects. What is left of the idea is to make each probe and each row cheaper, which is what was built.

**Does the copy's parallelism survive the source accessor's lock?** `GitSourceAccessor` takes one `Sync` for every read — `readBlob`, `maybeLstat`, `readDirectory`, `readLink`, `getFingerprint` each begin with `state_.lock()` — and libgit2's own documentation forbids the alternative: "Unless otherwise specified, libgit2 objects cannot be safely accessed by multiple threads simultaneously" (`docs/threading.md`, the pinned rev), with `git_odb` the one exception and `git_repository`, which `git_blob_lookup` and `git_tree_lookup` take, never named. So under any parallel copy the read *and the hash under it* stay on one thread at a time and only the write side overlaps. **What is not parallel, and the reading that settles it.** `GitSourceAccessor` (`git-utils.cc`) holds `Sync<State> state_` and every read begins with `state_.lock()`: `readBlob`, `pathExists`, `maybeLstat`, `readDirectory`, `readLink`, `getFingerprint`. So the read, and the hash that runs inside `readBlob`'s `drainInto`, are serialised whatever the pool does. A handle per worker was considered and refused for two reasons, one of them libgit2's own: `SourceAccessor` has no operation that makes a second handle, and adding one would mean adding it to every accessor; and libgit2's `docs/threading.md` at the pinned revision says "Unless otherwise specified, libgit2 objects cannot be safely accessed by multiple threads simultaneously" and "Use an object from a single thread at a time", exempting exactly "references and configuration snapshots" and, separately, "The `git_odb` object uses locking internally, and is thread-safe to use from multiple threads simultaneously" — `git_repository`, which `git_blob_lookup` and `git_tree_lookup` take, is never named, and upstream's own thread tests open one repository per worker (`tests/libgit2/threads/iterator.c`). The floor above says the lock costs the parallel copy about a third of its ceiling and leaves the rest, so nothing is owed here.

**What the naming is now worth, and what was not measured.** The phase split (`treeHash` alone, then the copy with the memo warm) was *not* re-run for the parallel binary, so no naming/copy split is quoted for it. What is measured: the copy of a tree the store already holds is 0.23 s at 40 000 files, where the whole first entry is 0.84 s; and the sequential split before this round was 0.64 s of naming against 1.05 s of copy. The naming is a different walk with a different bottleneck — the memo's rows — and is not parallelised in the same breath; measuring the split for the parallel binary is the first thing to do next.

## 7. Owed, and why

- **Resource failures.** Physical coalescing retains its pin/alias refusal seam and real SQL-retry discriminators. First claims allocate no auxiliary file, so the old injected full-directory refusal and its process-specific discriminator are retired. Auxiliary metadata publishes through SQLite; SQL, allocation and I/O failures follow the completion transaction boundary, without claiming equality with obsolete resource-failure traces (`01` §9.10, `08` K11).
- **Windows.** The object store shares nothing there; by inspection only, no Windows build or run (`01` section 13).
- **Two facts stated without a discriminating test**: the filter over the children of a case-hacked *directory* name descends by the on-disk name as `dumpPath` does (reachable only on the case-hack platform after two directory names collided), and `objectHashOf` refuses a tree deeper than `narMaxDepth` as `dumpPath` does. Both hold by construction now that there is one traversal (`src/libutil/include/nix/util/tree-traversal.hh`).

## 8. Rules for changing this code

Each rule names what enforces it today; what only review holds is said to be held by review. The rules that sections 2 to 5 already enforce — one suite per command line, a fix's test run against the unfixed code first, a mutation restored by an edit that changes the mtime, both platforms before a step is done, the environment facts a test asserts — are not repeated; the call-site questions are `08-store-model.md` section 2.

1. **A finite domain is enumerated from the lowest primitive, in code.** Before writing "for all X, P(X)" where X is listable — builtins, output modes, enum cases, protocol directions, description kinds, the readers of a column, the callers of a primitive — write the check that iterates the set from its source of truth and run it; enumerate the callers of the primitive that produces the value, not of the wrapper in hand, since a wrapper can be inlined at a call site a grep for the wrapper misses; grep a call's *name* and read every hit, since a one-line shape of its argument list misses a call split over lines. For an infinite domain, the generator must be shown to produce the case just added and to reach the sizes claimed. *Enforced by:* the templates `TextStoreTest.everyBuiltinAgreesOnProducedAndMaterializedInputs` (`src/libexpr-tests/text-store.cc`: callable names outside its exclusions, three selected shapes and declared remaining primitive arities; ordinary lambdas use one/two arguments) and `LocalStoreObjectsTest.gitMethodRefusesSha1AtEveryCreationEntry`; `LocalStoreObjectsTest.everyBuildModeEntersWithItsRepairFlag` (every build mode, its flag from `enterRepairFlagOf`, a `switch` without a `default` beside the enum), `ObjectHashLocalStore.everyPathInfoReaderAcceptsBothColumnRenderings` (the eight readers of a description's content hash, in the three shapes a form puts the two renderings in), `ObjectHashPathInfo.everyDescriptionKindCanBeSigned` (the four combinations of the two hashes a description can carry) and `maintainers/check-cache-domains.sh` (the fetcher cache's domains and their consumers, where C++ has nothing to iterate); the compiler, for a changed signature (the type enumerates the sites, which is why `ObjectHash` is a strong type and `narHash` a field that no longer exists); review, for a changed contract whose sites the compiler cannot see.

2. **Both protocol directions, always, with and without the feature.** A wire or format change is tested old→new and new→old with a binary built from master, with and without the feature or version the old side would need. *Enforced by:* `tests/functional/object-hash.sh`'s interop blocks under `NIX_REFERENCE_BIN` (section 2); `git-hashing/simple-sha1.sh`'s reference-binary block; `interop-old-daemon.sh` and `git-hashing/old-executable-root.sh`, whole tests under the same variable.

3. **Enumerate the readers before refusing a form.** A refusal at a parser or a name function is preceded by a list of every reader that parses the form — in particular what the garbage collector and `nix-store --verify` read on every row and every derivation they visit; a reader tolerates, a creator refuses. *Enforced by:* `ContentAddress.sha1GitFormIsReadable`, `DerivationAtermTest.sha1GitFixedOutputReads`, `LocalStoreObjectsTest.sha1GitRowIsReadVerifiedAndCollected`, each shown to fail under the refusing design by mutation (section 4).

4. **A concurrency claim gets an interleaving test, or the law says "unchecked".** A sentence of the form "X cannot happen while the collector runs" or "the link count keeps it" is accompanied by an interleaving unit test whose pause is a real seam (a `Source` that stops mid-NAR, a hook that fires mid-walk), or the law states that its concurrent form is unchecked and names the owed test. *Enforced by:* `LocalStoreObjectsTest.ingestionTreesSurviveAConcurrentSweep`, the interleaving `01` section 9.10 laws 4 and 5 name, which failed on the tree before the hold at five assertions (section 4); the single-path forms pinned by `sweepAndVerifyOnALiveRootWhoseTreeIsMissing`, `sweepTolerantOfAnUnenteredRoot` and `LocalStoreAutoGCTest.*`; the forms still owed are section 7's.

5. **A design decision carries its consequence list before the code.** Before a decision is built, the forms, peers, memos, stores and costs it changes are enumerated — the *stores* a rule governs (an upgraded store, a `--load-db` store, a `min-free` store), not only the case that raised it — and each consequence gets a check or an explicit "accepted, unchecked". *Enforced by:* `01` section 10, where each decision states its consequence; review, which refuses an entry without one.

6. **Correct by construction where the language can hold the boundary; a check that runs without judgment where it cannot; stated where neither reaches.** The compiler checks representations such as the strong `ObjectHash`; `maintainers/check-cache-domains.sh` checks its finite domain and plants five violations. Eager publication removes the temporal string/exec tokens and their checker. Behavioral tests cover publication, output order and C ownership; review states the remaining limits (`04` §§0.2 and 1.2).

7. **Counts come from artefacts; measure before explaining.** A number in these documents is pasted from a tool's output with the command beside it, or written with its arithmetic and marked `[derived]`; a number with neither has not been checked and says so. A performance sentence names its measurement; a causal explanation without one is marked `[hypothesis]`; a fix is placed where an experiment located the cause, not where a reading placed it. *Enforced by:* the convention of `README.md`; section 6 carries the command for every table; review.
