# Preserving identities and reducing ingestion work

The comparison base is `8aad447f0bace6be413963e897ad690247ad6aa2`, the branch base. The pinned input is Nixpkgs `6aefcda9401be8acc2b74244fb3b37520ea1f0a8`, on aarch64 Linux. `runs/nixpkgs-evaluation.py` records commands, binaries, environment, resource usage and raw samples. Cold means a new private store and fetcher cache; operating-system caches remain warm. Before timing, the helper checks every local source node against the pinned raw Git tree: bytes, executable bits, symlink targets and complete directory membership. This does not rely on status flags or attribute-normalized comparisons. GitHub cold times include network access.

## Finite workload

Each 32-attribute evaluation registers 3,693 store paths (3,694 for `path:`, which copies the input), with 27,517 reference edges: 3,140 derivation texts, two other texts, 542 plain-file sources, four executable-file sources and five directory sources. All 3,688 regular-file roots are smaller than 1 MiB. The complete input contains 89,979 nodes: 37,120 directories, 52,047 plain files, 809 executable files and three symlinks. Exactly 30,051 directories have one child. These counts enumerate the workload.

## Implementation and semantic boundaries

| Boundary | Change |
| --- | --- |
| Canonical entry → accessor | `getKnownEntry` carries the SHA-256 entry hash and mode. The canonical tarball writer opts in. Arbitrary SHA-256 repositories do not: raw modes, gitlinks and content-changing views can render another tree. Executable and symlink roots retain their synthetic root wrapper. |
| Valid store object → filesystem view | Registered object hashes supply fingerprints and plain-file/directory root identities. Input-addressed paths are not content identities. Unregistered views supply no such fact. Repair bypasses known entries and naming caches. |
| Git metadata → traversal | Listings retain their immutable parsed tree; later lookups borrow its entries instead of duplicating every sibling. Optional file sizes no longer trigger packed-object header reads before a memo lookup or file read. Reads still announce their size. |
| Worktree → Git status | The libgit2 patch skips ignore rules only for tracked-only diffs, retaining traversal, stat/content comparisons, attributes, modes and conflicts. Working trees remain filesystem sources even when Git reports them clean: index flags can suppress comparisons, and attributes can normalize bytes. A reported revision is metadata, not a name for those rendered files. Worktree HEAD substitution and revision fingerprints were removed. Export-ignore and LFS views also decline revision-only fingerprints because they consult external attributes. |
| Source identity → cached description | In-memory keys retain the current view fingerprint, its relative canonical path, address method, logical store directory and output name. The value is the resulting hash and store path, without a claim about destination presence. Accessor identity does not name a growing graft or allow list; unnamed views bypass the memo. Copying always roots and checks the requested destination. Equal logical directories in different physical stores share the description, not existence. Keys retain neither accessors nor stores. |
| Whole-view name → memo | Requested subtree roots are cached without eagerly persisting every descendant. These keys cannot survive a change of the whole-view fingerprint. Independently named Git objects retain recursive subtree memoization. Cache population never changes which store objects the evaluator writes. |
| Mutable path → ingestion route | An empty local store cannot already hold the destination: one traversal hashes and materializes the input directly, without spooling and replaying it. The database query stops at the first valid row and caches no absence; materialization still checks the final destination under its ordinary lock, including after concurrent registrations. A populated store names the source first so a present destination avoids staging. On a miss, ordinary ingestion names the bytes it actually copies; a mutable source can change after the preflight observation. |
| Known immutable blob → file copy | An accessor may already supply the canonical blob identity. The materializer probes for a holder before reading, then streams a miss directly into its canonicalized destination. It checks announced and delivered sizes. Mutable worktrees and repair retain hashing. |
| Buffered regular root → destination | The existing bounded reader observes the bytes once. A complete buffered file supplies its address before staging: root and check the destination, then create a hold and temporary file only for a miss or repair. A spill starts ordinary staging when its first bytes must be written. Both cases reuse the existing placement and registration operations. |
| Nested directories → copy scheduling | One bounded pool serves an unfiltered copy. The stateless `AllPaths` predicate identifies that case even when copied. Other filters may call the evaluator or have effects, so their traversal remains on the caller thread in depth-first order, including exceptions. A singleton stays inline because it has no sibling work to overlap. A full queue also makes the caller visit inline; while joining it helps only its own child jobs. A large subtree can use idle workers without spawning a pool at each level. Helping follows tree depth, and all children are joined before their directory scopes close, including on failure. |
| Pending text → flush | A successful flush requires every pending write to succeed; keep-going cannot suppress errors and let missing paths escape. Repair and keep-going use the existing strict per-object operation. Text addresses and references determine store paths. Blob hashes are computed only for objects that need writing; valid objects require no reference-order traversal. Address construction borrows reference sets instead of copying them. |
| Small memory stream → ingestion | Small streams already resident in memory use one dependency-graph worker. External and unknown streams retain parallelism. Flat/text and NAR content-address verification consumes incoming bytes instead of rereading restored files. |
| Concurrent misses → pending holder | The first completed file atomically claims the pending holder. Another worker that missed before that publication links to the winner; a previous lookup miss is not evidence that the blob remains absent. Both publication orders and executable modes are checked directly, and fresh parallel copies cover all eight widths. |
| Ingestion → database | Shards and the background writer are allocated on demand. Small ingestions register the path and holder rows in one transaction. Large copies retain incremental flushing. Each path retains its own ingestion identity and rows within a shared hold. Rows are candidate holders keyed by object, mode and ingestion: an unfinished ingestion cannot overwrite another ingestion’s registered candidate. Lookup enumerates registered valid candidates and forgets only the candidate whose observed file is invalid. Every overlapping writer owns a strong lease; no call borrows a raw pointer whose owner can finish first. Existence and reference-ID queries select only the indexed ID, avoiding unused description columns. |
| SQLite connection → WAL locks | The ZFS workaround checks the filesystem without opening the shared-memory file in the parent. Only ZFS needs a helper process to sync it. Closing an independent descriptor in the parent previously released all of its POSIX locks on that inode; a subsequent process could truncate the WAL index while it remained mapped, causing SIGBUS. The blob writer also preserves the configured journal mode. |
| Evaluator lifetime → source ownership | Expressions allocated in an arena borrow sources owned once by that arena. File-parse thunks use the same arena. Cached failed values borrow exceptions owned by evaluator memory, while escaped C++ exceptions retain independent ownership of their source positions. Growing parser containers use the arena’s existing owned pool before their final allocation, so parse failures and discarded nodes also release their storage. This releases store connections at evaluator destruction without relying on GC timing; cached errors are retained for that evaluator’s lifetime. |
| Transaction → validity cache | Cache publication follows commit. A rejected reference or cycle cannot leave a cached claim that a rolled-back path is valid. |
| Auxiliary bytes → tree/blob file | The unique temporary is inside the locked hold. Its original link protects the auxiliary address, including a replacement inode published by repair, removing a further link and immediate unlink. Exact readable permissions are set through the open descriptor before optional fsync. Auxiliary timestamps are not exposed tree metadata and no consumer reads them; POSIX auxiliary writes omit that update, while regular-file holders retain canonical timestamps. Auxiliary kind directories are made only when used; regular holders need none. Temporary names use the same 256 identifier shards as published names, removing the shared flat directory from parallel creation. Live holds release their owned links with descriptor-relative unlinking, avoiding metadata reads used only for the general deleter's unused freed-space estimate. Symlinks are never followed; dead holds keep general cleanup. A fresh hold name is claimed exclusively, including after PID reuse. Auxiliary publication/acquisition and final hold release take the namespace’s shared lock; a sweep takes its exclusive lock from root snapshot through deletion. This closes the link-count/unlink race and protects registrations newer than the snapshot. Whole-hold and whole-GC locking would prevent required ingestion progress. |

A holder is reusable only when it is a regular file with canonical permissions (`0444` or `0555` for the requested mode), mtime `1s + 0ns`, and matching inode, device and size; repair also checks its bytes. Tree equality alone is insufficient: linking would propagate noncanonical physical metadata. Invalid candidates are forgotten without modifying files belonging to store paths. The path canonicalizer also normalizes a nonzero nanosecond field when its seconds field is already one.

Reuse records the receiving ingestion's own candidate: collecting the donor must not erase the remaining file's witness. A complete ingestion replaces the previous candidate projection of the same path, including an empty projection; repeated optimisation therefore retains no duplicate history. Candidate selection orders physical inode classes before ingestion identities. Replacing a row or collecting one of several aliases cannot change the surviving class's rank. Independently completed misses must also share before publication. Registration reserves the SQLite writer, keeps the new candidates private, and reconciles colliding physical files against registered holders before exposing them. The additional filesystem walk occurs only for collisions; candidate metadata is not a substitute for the filesystem sharing law. A refused link must not promote an exceptional inode as a donor for later successful copies.

The representation still includes one file per auxiliary tree. There is no packed representation or shared directory entry change.

## Design audit

The question is whether the same evaluations can produce the same abstract store and results with less elapsed work. The existing filesystem-object model is the specification: a regular file's bytes and executable bit, a symlink's target, or a finite map of child names to objects. For an accessor `A` and path `p`, a supplied canonical entry must equal the entry hash of the object that `A` renders at `p`. Identity-preserving wrappers can forward it; filters and grafts must derive another identity or decline to supply one. A stored object's executable/symlink root wrapper is not its entry hash.

Ingestion's address must name the object it writes. A mutable filesystem has no stable identity: a preflight observation is not a promise about a later read. Applying the [reasoning and design guidance](../../../../ExtPackages/denotational-design/reasoning-and-design-guidance.md) exposed an unnecessary stronger contract in the initial optimization: retaining the entire preflight observation for replay. That machinery was removed. The path fetcher uses the existing naming and ingestion operations, and the copy scheduler remains private to its one consumer. No new snapshot representation is needed. An empty-store test chooses whether preflight could avoid work; it changes neither ingestion nor the set of registered results.

A union can forward a child’s name only when that child names the complete rendered subtree, including its domain. Agreement where children overlap does not establish that fact. The evaluator’s raw host view does not establish validity of an overlapping host occupant, so the special coherence policy was removed; ordinary union ownership and ancestor hiding determine which identities can be forwarded.

A pending holder names a completed file whose lifetime covers every borrower. A speculative directory copy can still fail and delete its partial subtree, so its rows remain private until the whole attempt succeeds. Successful rows then join the parent ingestion; conflicting inode classes use the same physical reconciliation as registration. An error after that publication aborts the ingestion and joins its workers before cleanup. This follows the existing completion boundary instead of adding rules to repair dangling claims after rollback. Durability remains at final publication, rather than repeating it for each speculative subtree.

The remaining mechanisms have distinct obligations: canonical identities avoid recomputing a known value; the naming memo retains only reusable facts; pending holders make concurrent copies share the first completed canonical inode; and registration publishes validity only after the transaction commits. Parallel directory work changes execution order while preserving the ordered tree fold and the lifetimes of its open directories. The existing general thread pool cannot join nested directory jobs while retaining these scopes; the bounded copy pool supplies that operation locally. The finite checks below and the complete store comparison are external counterchecks, not a formal proof.

## Verification

The libgit2 comparison enumerates 15,552 combinations: six HEAD/index/worktree node kinds × three ignore policies × attributes on/off × ignorecase on/off × unchanged/changed index contents × unchanged/changed/EOL-only worktree contents. All patched results equal the original pinned library. The six kinds are absence, regular, executable, symlink, directory and gitlink. Coverage is exhaustive within these dimensions, not every possible Git configuration. The patched library also passes its enabled upstream suites.

The naming-cache regression first failed against a result cached without its output-name and destination arguments. It passes with hash-only values, and constrains the full-description memo to include every pure naming argument while checking presence separately. Its 64 cases exhaust all four address methods × both first-call modes × both second-call modes × equal/different output names × equal/different logical store directories, always with distinct physical stores. A separate lifetime check establishes that the naming memo does not keep its source alive. Further regressions enumerate 128 graft/allow-list growth cases and 32 unnamed-file mutations; the former crosses named/unnamed components, both directory methods, both fetch modes and equal/different output names.

Regression tests cover the four supported root kinds, filtering, grafts, repair, canonical provenance, scoped-directory replacement, holder lifetimes and modes, failed registration and retry, and small/large source files. Nested-copy success and failure tests enumerate all eight supported worker counts. Mutable-path ingestion enumerates empty-store misses, populated-store hits and populated-store misses at every width, including a failed traversal followed by retry and both small and large files. Hold-layout tests enumerate all 256 shards for each of the three auxiliary object kinds. Existing suites cover the wider ingestion, signature, export, GC, overlay and evaluator write-set contracts.

The evaluator ownership diagnosis accounts for every surviving root-filesystem owner in the warm eight-attribute GitHub evaluation: 340 file-parse thunks and two source positions in a caught error trace. GDB resolved the store destructor breakpoints but none fired before exit. The two positions were independently compared to the evaluator’s root accessor control block. Lifetime regressions cover successful and cached parsing, caught failures, and an escaped error whose source remains readable after evaluator destruction. The corrected debug evaluator subsequently destroyed those exact root and mounted accessors and its LocalStore in a real eight-attribute GitHub evaluation. On a separate full copy of the prior benchmark state, the WAL shrank from 164,808,272 bytes to zero. The original database, WAL and shared-memory files retained their hashes and inodes. This establishes cleanup, independently of the still-required timing comparison.

The AST ownership survey covers all 28 concrete expression types. Only `ExprAttrs` and `ExprCall` retain growing parser containers. Their seven applicable lifecycle cases cover successful parsing, parse failure, binding failure, and discarded merged attrsets. An external PMR allocation counter observes zero outstanding allocations after evaluator destruction in every case.

The concurrent-read audit enumerates all 17 concrete production accessor classes and follows the actual materialisation routes. Independent Git accessors can share a repository's attribute cache: libgit2's `attr_file.c` checks file stamps outside the cache lock, and `futils.c` updates those stamps when external attributes change. Its cold-cache publication also precedes default-macro insertion, while macro lookup reads the same map without locking. One repository-owned mutex now encloses attribute lookup and interpretation, including status's indirect lookups. Accessor state precedes this mutex; network transfer and raw immutable object reads remain outside it. The concurrent regression covers four applicable views, two wrappers per view, two readers per wrapper, cold and refreshed attributes, and simultaneous status. This is functional coverage, not a deterministic race detector.

The flake fixtures distinguish mutable worktrees from immutable commits. Cache-hit and cached-error recovery assertions use explicit revisions and retain the test hook that rejects unnamed sources. Working-tree freshness checks enumerate both index flags, independently set and cleared, and require changed bytes to change evaluation while the pinned commit stays unchanged. A blanket requirement that every flake source have a fingerprint would contradict this distinction, including impure evaluation through an overlapping physical store path.

Permission validation enumerates all 4,096 portable mode patterns through the production metadata predicate. The corresponding physical holder checks exercise all 1,024 patterns without setuid/setgid bits, including sticky; Nix's build sandbox explicitly forbids creating the other patterns. Lookup, forgetting and non-mutation assertions remain unchanged. This separates the complete metadata domain from filesystem fixtures the sandbox permits.

This audit does not establish that every possible `SourceAccessor` subclass supports concurrent reads. In particular, `RemoteFSAccessor` has unsynchronised cold maps; the supported copy routes populate the one enclosing store object before scheduling children, or return its completed NAR accessor directly. Arbitrary byte callbacks also retain their own concurrency obligations. No general capability framework or speculative locks were added.

The corrected write-failure regression enumerates 32 flush cases. Against the old flush, exactly eight fail: keep-going enabled without repair, across both dependency shapes and every failure position. The corrected implementation passes all 32 and retains pending objects for retry. File-lock checks enumerate 12 acquisition cases and 18 mode transitions. The old RAII constructor fails to release immediately acquired waiting locks. Separate Linux syscall-result injection for shared and exclusive waiting locks also fails against the old EINTR handling and passes when interruption retries after cancellation checking. These checks exercise the returned kernel error; they do not claim to test real signal delivery. Windows locking changes have not been run on Windows.

The WAL-lock regression first failed against the old constructor and passed after the fix. A child process uses `F_GETLK` to observe that the first connection keeps its locks before, during and after a second connection. Both WAL and rollback-journal blob writes are tested. The crash was captured twice in a twenty-run serial GDB reproduction: stacks ended in `walFindFrame` and `walIndexReadHdr`. [SQLite's locking documentation](https://sqlite.org/howtocorrupt.html#posix_advisory_locks_canceled_by_a_separate_thread_doing_close_) and [`unixLockSharedMemory` in the pinned 3.51.2 source](https://github.com/sqlite/sqlite/blob/version-3.51.2/src/os_unix.c#L4839) explain the mechanism: an absent dead-man lock authorizes truncating the shared-memory index.

The build preceding the second audit passed 2,377 unit tests (435 evaluator, 136 fetcher, 858 utility and 948 store tests), with two pre-existing skips. The store suite includes all 120 three-file inode-partition, minimum-class, registration-order and mode cases, two actual donor-GC cases, and eight speculative-subtree rollback/merge cases. The independent SQL check passes all 5,760 enumerated visibility and physical-order cases. All 12 real overlay tests and five object-store/optimisation/GC functional tests passed; the final Git change also passed the three relevant fetch/subtree/object-store functional tests. All 448 filter-effect cases pass, and reinstating the previous scheduling body makes that regression fail. The initial benchmark checker passed 18 controls; the second audit below found and corrected an omitted byte-context domain. These results apply to aarch64 Linux; they do not replace the optimized performance comparison below.

## Measurements

A diagnostic made by copying a populated store was rejected: every copied holder had a different inode from its database witness (0 of 3,465 matched, versus all 3,702 in the original). A freshly seeded debug run retained all 3,702 witnesses. Its warm eight-attribute Git syscall profile still showed 6,303 `mkdirat`, 9,539 `unlinkat` and 3,151 `linkat` calls. The unchanged output addresses and valid destination rows distinguish repeated temporary ingestion from new store results. These are structural observations from a debug binary, not elapsed-time benchmark results. Ordinary copies of an indexed store cannot establish representative warm holder behaviour.

Use `runs/nixpkgs-evaluation.py benchmark` with explicit base and branch executables, the two local Nixpkgs paths, an unused output directory, and the CPU affinity. The helper measures all three URI schemes, first-use 32-attribute evaluations, and repeated 8- and 32-attribute evaluations after seeding with 32 attributes. It balances executable order separately for each case and records every sample. `runs/compare-store-graphs.py` checks the entire registered graph and exact contents after an injective address mapping, including executable derivation files. Its benchmark-output option also binds every returned attribute’s derivation path to that mapping. Each separate cold store needs its own graph comparison. `runs/check-benchmark-methodology.py` supplies positive controls and planted counterexamples for these checks. Final measurements are recorded separately from implementation changes.

Twenty repeated warm evaluations were profiled separately using `armv8_pmuv3_1/cycles/u`, period 10,000,000. Warm Git's status path improves from 1,449 to 1,024 samples, while the branch's required raw tree fold accounts for 1,722 samples. Clean Git status is not a raw-byte identity: the pinned implementation bypasses comparison for index flags, accepts matching metadata, and otherwise applies Git filters. The branch must observe those bytes. Allowlist naming spends 317 self samples finding covering prefixes. A minimal prefix antichain preserves the admitted and fully exposed subtree domains, making one predecessor sufficient; it does not ask a hidden inner accessor for a name.

Warm GitHub's source-copy path rises from 95 to 555 samples, while parsing rises from 616 to 696. Repeated union ownership checks, address construction and destination queries dominate the increase; holder publication and evaluator destruction do not. Syscall counts independently show 4,860 to 79,183 `openat2` calls and 173 to 37,601 `newfstatat` calls. A source's absence in the host filesystem cannot be cached across arbitrary mutation. Instead, the second pass retains complete pure naming results, reuses its one root-name observation throughout an operation, and resolves mounted suffixes directly. Descendant identities and actual destination validity remain separate observations.

Cold path copying has 112 of 757 user-cycle samples in holder linking, including 106 in the registered-holder SQLite lookup. SQLite's internal connection mutex duplicates the primary connection's `_state` exclusion; the opt-in removal applies only to that audited connection. Transaction-local IDs also avoid repeated queries for the finite set of outputs and references. Syscall counts show roughly 37,000 additional auxiliary files, including their metadata and publication operations. User-cycle profiles cannot attribute kernel time, and strace timing perturbs parallel work; only its call counts are used here.

The graph checker initially rejected addresses attached to compiler options such as `-L/nix/store/...`. Opaque derivation strings do not carry enough syntax to justify that left-token boundary. The check now defines exact byte equality under substitution of every complete known address, including all left contexts; a longer distinct basename remains distinct. This is address alpha-equivalence, not a proof about arbitrary embedded programs. The new controls enumerate all 256 left and all 256 right byte contexts, alongside content, mode, graph and output counterexamples. No whitelist of compiler options is used.

All eighteen store-pair comparisons passed: three warm stores and fifteen distinct cold stores, each checked with its own injective mapping. Each comparison contains 27,517 reference edges and 4,505 declared derivation outputs. All 156 evaluation outputs are bound exactly once to their actual store pair; the checker rejects a mapping borrowed from another cold store. The revised methodology checker passes 23 controls. Both checker hashes and per-pair results are retained in the sample report.

The second implementation pass treats temporary roots as a set owned by one live, linked, locked file. Multiple store handles therefore need distinct files, even in one process. A complete record precedes the collector handshake; successful set membership follows it. Interrupted appends retain their unfinished record and continue that exact byte stream on retry, because rewriting its tail could splice bytes seen by a concurrent reader. A failed socket exchange discards its connection, preventing a delayed acknowledgement from satisfying a later request. The file is removed before its POSIX lock is released, and a collector never unlinks a replacement through an already-unlinked descriptor.

Auxiliary holds denote typed object addresses, not particular inodes. Repair can replace a corrupt inode without releasing an existing hold on that address. The collector now enumerates those claims separately from reachable-tree traversal. Removing just that retention rule causes 24 of 36 repair cells and 18 of 48 hold-name cells to fail; restoring it passes all three related tests. Internal auxiliary timestamps are unused representation metadata. Permission-only publication still sets the exact readable mode before fsync, independently checked across all 512 umasks and both modes. Regular holders retain the canonical timestamp predicate.

The path-order check uses an independent unsigned-byte component model over 769 paths and all 591,361 ordered pairs. The previous comparator disagrees in 292,864 pairs with signed plain `char`; the corrected comparator agrees in both signed and unsigned builds. Prefix admission also checks every subset of its finite prefix domain. Scoped filtering composes coordinates once while retaining each listing's immediate-child snapshot and its physical directory scope. Its tests cover 1,890 admission transitions, 20 escaping exceptions and a real directory replacement. Root-name reuse covers all four root kinds, both fetch modes and the three relationships to an explicit whole-view name.

The second-pass debug build passes 2,395 unit tests (435 evaluator, 141 fetcher, 860 utility and 959 store), with two existing skips. Four temporary-root negative controls separately restore late publication, duplicate registration, missing partial-write recovery and failed-socket reuse; each fails its targeted regression, and all pass after restoration. These checks precede the final accepted-connection ownership correction and the next optimized timing run.

A Linux syscall-injection control unlinks the first newly created roots file immediately before its write lock, without writing the collector marker. Acquisition retries and the registration test passes. Removing only the linked-inode check fails that same injected run; restoring it passes again. This exercises the actual missing-file state, independently of the two-handle tests.

The accepted-connection correction passed the rebuilt store suite (960 tests), all five targeted object-store/hash/optimisation/GC functional tests and all twelve real overlay tests. Connection ownership is published under the map lock before its worker can finish; shutdown uses the descriptor while that same lock still proves its ownership, then joins after releasing the lock. Six lifecycle cases cover client completion and server shutdown, without claiming deterministic reproduction of thread scheduling races. The combined current unit count is 2,396 passing tests and two existing skips.
