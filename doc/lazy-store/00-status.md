## Semantic model

A source denotes a filesystem tree: regular-file bytes and executable bit, a symlink target, or a finite directory map. SHA-256 object naming includes the synthetic wrappers for executable and symlink roots. Output name and ingestion method also participate in store-path addresses. Text and SHA-256 NAR addresses admit references; Flat and Git fixed-output addresses require none. Writable evaluation publishes Text objects before returning their paths, including unobserved objects; read-only evaluation computes addresses without writing.

Regular contents live in store paths. Database candidates identify holders by object, mode and ingestion; reuse requires a registered valid path, physical checks and the recipient's own witness. Publication reconciles inode classes before exposing candidates. Directory bodies and symlink targets are owned metadata published with the same completed ingestion. An on-demand lease protects completed outputs before registration and temporary coalescing links. Private row staging needs no lease directory. Upper-only overlay authority, repair, and physical sharing remain governed by the [store model](08-store-model.md).

Names describe the complete rendered source view. Mutable worktrees remain filesystem sources even when Git reports them clean; status and attribute normalization do not prove raw-byte identity. Filters, unions and grafts preserve or derive identity. Address memos do not prove destination existence: a copy registers a temporary root and checks the requested store path. Completed evaluator requests record an earlier operation, not current mutable bytes; filtered, asserted, reference-bearing and repair requests bypass that memo. Ordered traversal joins accepted children before directory scope exit, with concurrency requiring source, filter and callback permission.

The [specification](01-specification.md) and [derivation](04-derivation.md) define the contracts. Work follows the [design guidance](/home/connorbaker/ExtPackages/denotational-design/reasoning-and-design-guidance.md): enumerate finite domains, derive operations from their meanings, and retain external checks that can reject an implementation.
