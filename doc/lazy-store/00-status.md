## Semantic model

A source denotes a filesystem tree: regular-file bytes and executable bit, a symlink target, or a finite directory map. Its SHA-256 object hash is computed from that tree, including the synthetic wrappers for executable and symlink roots. Source store paths also depend on their name, ingestion method and references. In writable evaluation, Text producers publish their objects before returning their paths, including unobserved objects. Read-only evaluation computes their addresses without writing.

Regular-file contents live in store paths. The database retains candidate holders per object, mode and ingestion; lookup requires a registered valid path. Reuse checks physical metadata and records the recipient's own witness, and publication reconciles inode classes before exposing candidates. Directory bodies and symlink targets are owned metadata in `AuxValues`, published with the same completed ingestion. Every reused body becomes part of the recipient's projection. An on-demand locked lease protects completed outputs before validity registration and temporary coalescing links. Staging private rows alone needs no lease directory; direct publication commits validity and projection together. Whole-store collection removes stale projections after dead-lease cleanup, without an auxiliary mark graph. Upper-only overlay authority and regular-file sharing are unchanged (`08-store-model.md`).

Names describe the complete rendered source view. Mutable worktrees remain filesystem sources even when Git reports them clean; status flags and attribute normalization cannot prove raw-byte identity. Filters, unions and grafts must preserve or derive that identity. Source-to-store memos retain addresses, not destination existence: a copy registers a temporary root and checks the requested store path. Hashing and materialisation share a bounded ordered scheduler; concurrent execution requires separately established source, filter and callback permissions, and every accepted child finishes before its directory scope closes.

Completed evaluator requests are a separate kind of fact: the result of an earlier operation, identified by resolved source, method and output name. Reuse does not identify current mutable bytes. Filtered, asserted, reference-bearing and repair requests bypass this memo; their existing validation and destination-reuse rules still apply. Mounting or explicit reset retires completed requests.

The [specification](01-specification.md), [implementation derivation](04-derivation.md) and [store model](08-store-model.md) define these contracts. Changes are vetted against the [reasoning and design guidance](/home/connorbaker/ExtPackages/denotational-design/reasoning-and-design-guidance.md): enumerate finite domains, derive operations from their meanings, and retain external checks that can reject the implementation.

## Implementation and evidence

Text publication uses one Store operation; the evaluator's buffer/flush wrappers are removed. Source and cached-object materialization share traversal, scoped writers and the ordered directory fold. Buffered Flat publication avoids a physical reread, while staged/cross-device copies retain their projection walk. Leases are acquired on demand, and legacy NAR hashing is operation-scoped. Physical holder checks, repair, security walks and compatibility validation remain required.

Streamed placement now respects a completed refusal instead of retrying and publishing a pending holder; its regression discriminates both executable modes. Attribute consumers borrow eager values and own lazy results, sharing conversion before result consumption. Metadata constructors borrow their input while constructing their own fields; JSON parsing borrows the input object and reuses the existing Hash serialization. Import verification returns its Hash directly.
