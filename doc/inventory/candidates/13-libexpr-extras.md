105. **`MakeBinOp`/`MakeBinOpMembers` macros expand to six near-identical AST node classes.** `MakeBinOpMembers(name, s)` synthesises `pos`/`e1`/`e2`, two constructors, `show` (always wrapping `e1 s e2` in parens), `bindVars` (`e1->bindVars; e2->bindVars`), an `eval` declaration, and `getPos`. `MakeBinOp(name, s)` wraps it in `struct name : Expr { ... }`. Used six times for `ExprOpEq`, `ExprOpNEq`, `ExprOpAnd`, `ExprOpOr`, `ExprOpImpl`, `ExprOpConcatLists`, plus a partial reuse where `ExprOpUpdate` opens its struct manually and embeds `MakeBinOpMembers(ExprOpUpdate, "//")` so it can override `evalForUpdate` alongside the generated members. A CRTP base `BinOp<Derived>` with a `static constexpr std::string_view symbol` would replace the macros and let `ExprOpUpdate` inherit instead of carving out a manual special case.
    - ../verified/12-libexpr-parse.md
    - **Validation:** VALID. Plain CRTP — no template trickery beyond `static constexpr std::string_view symbol = Derived::symbol;`. Eliminates both `MakeBinOp` and `MakeBinOpMembers` macros. Effort: small.
    - **Branch:** `vibe-coding/cleanup/libexpr` (`template<class Derived> struct BinOp : Expr` carries `pos`/`e1`/`e2`, the two constructors, `show` (using `Derived::symbol`), `bindVars`, and `getPos`. Each derived `Expr*` declares its own `eval` override one-liner so the out-of-line definitions in eval.cc remain `void ExprOpEq::eval(...)`-style. `ExprOpUpdate` is no longer a special case — it inherits from `BinOp<ExprOpUpdate>` like the others and adds its private `eval(EvalState &, Value &, Value &, Value &)` helper plus its `evalForUpdate` override directly.)

106. **`parseExprFromBuf` and `parseReplBindingsFromBuf` duplicate the entire scanner/parser skeleton.** Both construct identical `LexerState`/`ParserState`, call `yylex_init_extra`, install a `Finally` for `yylex_destroy`, run `yy_scan_buffer`, instantiate `Parser`, and call `parser.parse()`. The repl variant adds exactly two things: a `setReplBindingsMode(scanner)` call between `yy_scan_buffer` and the `Parser` construction, and a `dynamic_cast<ExprAttrs *>(state.result)` plus two `assert`s on the way out. The two start-rule alternatives in the grammar (`expr` vs `REPL_BINDINGS binds1`) already encode the mode difference; a single `parseFromBuf<T>(text, ..., bool replMode)` template returning `T *` would consolidate the bodies.
    - ../verified/12-libexpr-parse.md
    - **Validation:** VALID. Single `template<bool replMode>` helper, or runtime-bool parameter, returning `Expr *` with the repl variant doing the cast at the public entry point. Effort: trivial.
    - **Branch:** `vibe-coding/cleanup/libexpr` (static `parseFromBuf(..., bool replMode)` driver; both public entry points are wrappers; the `dynamic_cast<ExprAttrs *>` and asserts moved to the repl wrapper)

107. **`Printer::shouldPrettyPrintAttrs` and `shouldPrettyPrintList` are byte-for-byte equivalent modulo the element accessor.** Both check `!options.shouldPrettyPrint() || empty`, return `true` when `size > 1`, fetch the single element (`v[0].second` for attrs, `list[0]` for lists), guard a null pointer, call `state.forceValue(*item, item->determinePos(noPos))`, and return `itemType == nList || nAttrs || nThunk`. The only meaningful difference is that the attrs version dereferences `v[0].second` (the `Value *` half of an `AttrPair`) while the list version uses `list[0]` directly. A small `shouldPrettyPrintSingleton(state, Value *)` helper (or a templated `shouldPrettyPrint<Container>(c, extractValue)`) would dedupe the body and leave each public method as a one-line dispatch.
    - ../verified/12-libexpr-parse.md
    - **Validation:** VALID — but borderline. Two methods with a single accessor difference; smallest possible "duplicated code" cluster. Keep but accept it is borderline. Effort: trivial.
    - **Branch:** `vibe-coding/cleanup/libexpr` (private `shouldPrettyPrintNonEmpty(size_t, Value *)` helper)

108. **`LazyPosAccessors` and `LazyFetcherAttr` re-implement the same internal-primop-plus-pre-applied-thunk machinery.** Both build an unregistered `PrimOp` whose `impl` decodes a forced argument, then construct a `Value` for the primop (`mkPrimOp`) and a `Value` carrying the deferred state (an integer-encoded `PosIdx` in `LazyPosAccessors::operator()`, an `ExternalValueBase` subclass in `emitLazyAttrThunk`), and finally splice them together with `dest.mkApp(vPrimOp, vState)`. `LazyPosAccessors` is a static-instance struct holding `primop_lineOfPos`/`primop_columnOfPos` plus pre-built `lineOfPos`/`columnOfPos` `Value`s; `emitLazyAttrThunk` builds a function-local `static PrimOp forcePrimOp` and allocates fresh `Value`s on each call. A generic `mkLazyValueThunk(state, primFn, stateValue)` helper (templated on the state encoding) would unify both at the cost of one extra `Value` allocation in the int-encoded case.
    - ../verified/12-libexpr-parse.md, ../verified/14-libfetchers.md
    - **Validation:** PARTIALLY VALID. The state encodings genuinely differ (int packed into `Value::Int` vs heap-allocated `ExternalValueBase`), and the pre-allocation pattern is asymmetric (one is a static-instance struct, the other allocates per-call — wasteful, could be unified with the pre-built shape). A `mkLazyValueThunk(state, PrimOp & primop, Value * stateValue)` helper unifies the splice step. Pre-allocating the primop `Value` for `__forceLazyFetcherAttr` (the way `LazyPosAccessors` does) is an independent win. Effort: small.

The two checks accept the same set of identifiers (modulo whether `_` is a permitted leading char in both cases). Factoring `isVarName` into a public helper and having `printIdentifier` call it would make the identifier classification a single source of truth.
